## File Policy Summary

Future staging may include only reviewed source, documentation, public web assets, public-safe evidence, package metadata, lockfile, and workspace configuration.

Future staging must exclude local env files, local runtime databases, runtime logs, browser state, generated caches, build outputs, Hardhat outputs, local memory folders, raw or private JSON variants, wallet exports, and credential material.

Before any broad staging command is considered, every candidate path must be reviewed against the include and exclude policy.

## Workflow Readiness Summary

## Local-Advisory Boundary

Current artifact and provenance outputs remain `local-advisory`. They do not prove immutable source identity, protected workflow execution, required-check enforcement, protected artifact upload identity, release tag authority, or staging promotion authority.

Protected CI can supersede local advisory evidence only after:

- `.git=True`
- `.github=True`
- `.github/workflows=True`
- reviewed workflow path exists
- immutable source commit is recorded
- workflow run id is recorded
- required checks are enforced by repository settings
- artifact manifest and provenance report are regenerated by protected CI
- upload metadata includes source commit, run id, file list, hashes, retention, manifest hash, report hash, and verification decision
- release owner and approval timestamp are recorded

## Stop Conditions

Stop and report before continuing if any of these occur:

- `.git` appears without Gate A approval
- a commit appears without Gate B approval
- `.github/workflows/ci-source-provenance.yml` appears without Gate C approval
- `scripts/ci` appears without explicit helper-script approval
- repository settings are changed without Gate D approval
- broad staging includes excluded surfaces
- scan output includes matched values instead of redacted metadata
- local advisory evidence is described as protected CI provenance

Cleanup or history-changing actions after an unauthorized repository, commit, workflow, helper, or repository-setting change require separate explicit cleanup approval.
