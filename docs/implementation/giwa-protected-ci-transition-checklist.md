# GIWA Protected CI Transition Checklist

## Purpose

This checklist defines what must be true before local-advisory evidence can be superseded by protected CI evidence. It is not a repository settings change, workflow creation step, or deployment approval.

## Current Authority

Current authority is `local-advisory`.

| Capability | Current state |
| --- | --- |
| Source commit authority | blocked |
| Workflow run authority | blocked |
| Required-check enforcement | blocked |
| Protected artifact upload identity | blocked |
| Release tag authority | blocked |
| Staging promotion decision | blocked |

## Required Transition Evidence

Protected CI can supersede local evidence only when all rows are complete:

| Requirement | Required evidence |
| --- | --- |
| Repository initialized | `.git=True` after Gate A approval |
| Initial commit created | source commit recorded after Gate B approval |
| Workflow created | `.github/workflows/ci.yml` after Gate C approval |
| Required checks configured | Gate D approval plus repository settings evidence |
| Workflow run authority | workflow run id from the approved repository |
| Source binding | immutable source commit tied to workflow run id |
| Lockfile state | frozen install passes without drift |
| Artifact manifest | regenerated by protected CI |
| Provenance report | regenerated by protected CI |
| Verification | protected CI provenance verification passes |
| Upload metadata | run id, source commit, file list, byte counts, hashes, retention, manifest hash, report hash, decision |
| Release governance | owner and approval timestamp recorded |

## Required Check Names

Branch protection must use these exact check names:

```text
source-provenance
workflow-command-boundary
web-checks
protocol-checks
contracts-checks
node-syntax-checks
safe-scans
workspace-checks
artifact-provenance
```

Required checks must have completed successfully in the repository before they can be enforced. Job names must remain unique across workflows to avoid ambiguous required checks.

## Protected Artifact Naming

Local files keep the `local-*` names and `local-advisory` authority. Protected CI output should use staging-named artifacts for release routing:

```text
docs/evidence/giwa-staging-artifact-manifest.json
docs/evidence/giwa-staging-provenance-report.json
```

If a later approved workflow reuses `local-*` names, those files must include protected authority metadata and must not be confused with the Sprint 22/23 local advisory outputs.

## Blocker Register Updates

After any approved repository, workflow, or branch-protection action, update:

```text
docs/implementation/giwa-staging-blocker-register.md
```

Record owner, timestamp, evidence path, changed blocker rows, and remaining blocked state for:

- source provenance
- protected CI
- rollback
- static fallback

## Rollback And Cleanup Rules

Rollback can replace app artifacts and lock new writes, but it cannot reverse public GIWA Sepolia evidence.

If a future action partially succeeds without approval:

- stop all related actions
- keep promotion blocked
- do not push, tag, deploy, create workflow files, or change repository settings
- report path and class only for any excluded surface
- require explicit cleanup approval before removing repository metadata, workflow files, helper scripts, commits, or repository settings

## Exit Criteria

The protected CI transition is ready only when:

- four approval gates are explicitly recorded
- required check names match actual workflow job names
- protected CI has produced a successful run
- artifact and provenance outputs are regenerated by protected CI
- local advisory outputs are no longer used as release authority
- release owner and rollback owner are recorded
- staging promotion remains blocked until a separate release approval is complete
