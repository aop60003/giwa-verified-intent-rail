# Live Demo Sprint 12 Snapshot Schema

`live-demo-sprint12-snapshot.json` is a commit-safe export of one matched local live MVP run. It is generated only after the live verifier has matched a submitted GIWA Sepolia deposit transaction and created a dynamic receipt.

## Output Files

```text
docs/evidence/live-demo-sprint12-snapshot.json
apps/web/public/live-demo-snapshot.json
```

Both files contain the same public JSON payload.

## Required Top-Level Fields

- `schemaVersion`: string literal `1`
- `source`: string literal `live`
- `capturedAt`: ISO timestamp generated by the export command
- `liveUrl`: local demo URL used for the rehearsal
- `run`: public manifest and run summary
- `transactions`: public approve/deposit transaction hashes
- `verifier`: local verifier decision summary
- `receipt`: dynamic receipt payload and canonical receipt bytes

## Run Object

- `runId`
- `wallet`
- `campaignId`
- `missionId`
- `status`: string literal `matched`
- `intentHash`
- `expiryUnix`
- `createdAt`
- `updatedAt`
- `manifest.chainId`
- `manifest.target`
- `manifest.selector`
- `manifest.asset`
- `manifest.amountBaseUnits`
- `manifest.spender`
- `manifest.maxAllowanceBaseUnits`

## Transactions Object

- `approveTxHash`: public hash or `null`
- `depositTxHash`: public hash
- `submittedAt`: ISO timestamp from the live store

## Verifier Object

- `decision`: string literal `matched`
- `failureReason`: `null`
- `verifierInputHash`
- `canonicalVerifierInputPayload`, when the selected live DB stores the canonical verifier input row
- `canonicalVerifierInputPayloadBytesHex`, when the selected live DB stores the canonical verifier input row
- `replayBoundary`, when a retained legacy Sprint 12 snapshot predates the canonical verifier input row
- `decisionTxHash`: `null`
- `issuedAt`: Unix timestamp

Sprint 12 uses a local standard RPC verifier decision. It does not emit a verifier transaction.

Sprint 14 adds replay fields so reviewers can recompute `verifierInputHash` from public evidence. Snapshot export fails when the stored verifier input row is missing or does not recompute.

The checked-in Sprint 12 fresh wallet snapshot is retained as public run evidence from the browser-wallet rehearsal. Its live DB predates the stored `verifier_inputs` row, so the snapshot includes `verifier.replayBoundary` instead of synthetic canonical verifier input fields. Do not backfill those fields by hand. Use `docs/evidence/giwa-sepolia-mvp-evidence.json` for replayable static evidence, or rerun the live verifier on a DB that stores `verifier_inputs` before regenerating this snapshot.

## Verifier Replay Boundary Object

When present, `verifier.replayBoundary` must include:

- `canonicalVerifierInputPayloadAvailable`: boolean literal `false`
- `canonicalVerifierInputPayloadBytesHexAvailable`: boolean literal `false`
- `reason`: bounded string explaining why canonical verifier input is not present
- `exportCommandFailsClosedWhenVerifierInputMissing`: boolean literal `true`
- `replacementSource`: public-safe pointer to the replayable evidence source or rerun requirement

## Receipt Object

- `receiptHash`
- `payload`: parsed dynamic receipt payload
- `canonicalPayload`
- `canonicalPayloadBytesHex`

The receipt payload is testnet-only mock vault action evidence. Flashblocks data is not part of final confirmation.

## Export Failure Rules

The export command fails without writing a synthetic snapshot when:

- the selected live DB path does not exist
- no run has `status: matched`
- the matched run lacks submitted transaction evidence
- the matched run lacks a matched verifier decision
- the matched decision lacks a stored dynamic receipt
- the matched decision lacks a stored canonical verifier input
- `verifierInputHash` or `receiptHash` does not recompute from the stored canonical payloads
